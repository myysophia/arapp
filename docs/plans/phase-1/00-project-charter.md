# 00 项目章程（Project Charter）

## 1. 目标与成功标准
- 目标：在 10-12 周内交付中国大陆首发的 iOS 花粉风险 MVP，并完成文档先行治理。
- 成功标准：`docs/plans/phase-1/` 的 13 份文档齐备、评审通过、可直接指导实现。
- 业务结果：形成“匿名可用 + 登录可选 + 风险提醒”闭环。

## 2. 范围与非范围
- 范围：产品定义、UI 规格、Supabase 认证与数据库、API 契约、提醒、国际化、合规、测试、发布运维。
- 非范围：本阶段不写业务代码、不接入付费墙、不建设 B2B 功能。

## 3. 输入/输出与接口
- 输入：`deep-research-report.md`、既定产品决策、Supabase 技术路线。
- 输出：13 份模块文档与统一术语/字段字典。
- 接口：以 `05-db-schema-supabase.sql.md` 与 `06-api-edge-functions-contract.md` 为唯一真源。

## 4. 数据模型与约束
- 统一命名：`user_id`、`device_id`、`location_id`、`threshold_level`、`risk_overall`。
- 风险等级范围：`0-5`，全链路一致。
- 客户端仅调 Edge Functions，不直连业务表。

## 5. 异常与降级
- 数据源异常：返回最近有效缓存，并显示更新时间。
- 推送异常：记录失败事件，按重试策略执行。
- 登录异常：允许用户继续匿名使用。

## 6. 安全与合规
- 采用 Supabase Auth + RLS。
- 敏感信息最小化采集，位置与通知权限分离授权。
- 设置页提供数据删除入口与隐私政策入口。

## 7. 埋点与可观测性
- 核心埋点：`onboarding_complete`、`view_today_risk`、`set_alert_threshold`、`auth_success`。
- 运行指标：API 成功率、缓存命中率、推送成功率、崩溃率。

## 8. 测试与验收
- 文档验收：13 份文件齐全、章节完整、命名一致。
- 方案验收：05 与 06 字段一致；02/08/10 可追溯。
- 质量门槛：无空章节，无冲突术语。

## 9. 依赖与里程碑
- 依赖：Supabase 项目、Apple 开发者能力、数据源准入结论。
- 里程碑：D1-D10 完成文档落盘与评审闭环。

## 10. 假设与默认值
- 首发市场：中国大陆。
- 国际化首版：`zh-Hans + en`。
- 登录策略：匿名先用，登录可选（Google/GitHub/Apple）。
- 本阶段仅做文档，不做代码实现。
