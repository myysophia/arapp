# 08 国际化与本地化规格（i18n/l10n）

## 1. 目标与成功标准
- 目标：首版支持 `zh-Hans + en`，实现界面、通知、格式化统一本地化。
- 成功标准：核心页面与通知文案 100% key 化，双语切换无缺失。

## 2. 范围与非范围
- 范围：UI 文案、错误文案、通知模板、时间数字单位格式化。
- 非范围：第三语言、地区化运营文案系统。

## 3. 输入/输出与接口
- 输入：系统语言、用户偏好语言、`lang` 参数。
- 输出：本地化文案、格式化时间/单位、通知文本。
- 接口：`PATCH /v1/user/preferences` 维护 `locale`。

## 4. 数据模型与约束
- 支持语言：`zh-Hans`、`en`。
- 回退链：`zh-Hans -> en`，`en -> en`。
- 单位制：`metric | imperial`（首发默认 metric）。

## 5. 异常与降级
- 缺失 key：回退英文并记录日志。
- 格式化异常：回退 ISO 时间字符串。

## 6. 安全与合规
- 本地化文本不得包含误导性医疗承诺。
- 隐私与同意文案必须双语等价。

## 7. 埋点与可观测性
- 埋点：`switch_locale`、`fallback_locale_triggered`。
- 指标：缺失 key 数、回退触发率。

## 8. 测试与验收
- 双语切换后页面即时刷新。
- 文案长度压力测试（按钮、标题、卡片）。
- 通知模板参数渲染正确。

## 9. 依赖与里程碑
- 依赖：UI 文案 key 清单、通知模板清单。
- 里程碑：第 4 周完成 i18n 基础；第 8 周完成双语回归。

## 10. 假设与默认值
- 默认跟随系统语言。
- 用户手动设置优先级高于系统语言。
